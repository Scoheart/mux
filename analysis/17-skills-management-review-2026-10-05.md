# Skills 管理复核与修复

日期：2026-10-05。基于 v1.9.0 的本地实现继续审查。本文记录发布前复核与验证；正式交付以 GitHub Release 为准。

## 结论

本轮确认了生命周期写入、观测元数据、风险确认和详情定位中的具体问题，已在对应 Core 与界面入口修复。最重要的是：中央同名替换不能撤销已有消费者；当前文件的指纹与安装记录必须分开；列表聚合不能代替实际副本的操作身份；风险确认必须绑定原计划。

最初在隔离 HOME 的编译后 CLI 中复现了两个问题：已禁用的消费关系在中央重新安装后消失；中央正文合法修改后，Agent 状态仍为 `synced`。修复后的验证记录见文末。这里的源码复核与定向接口检查不等于全量故障注入验收。

## 主要调用链

```mermaid
flowchart LR
  S[本地 / GitHub / 归档来源] --> R[解析与私有 staging]
  R --> P[Core 计划：内容、风险、目标与哈希]
  P --> C[确认原计划并再次校验]
  C --> A[中央资产与消费关系]
  A --> I[实际内容 / 链接 / desired 观测]
  I --> U[CLI 和 Desktop]
```

中央资产由名字标识，但同名中央、Agent 目录、独立外部副本分别拥有不同 `identity`。界面可以按名字合并卡片；写操作必须针对实际副本，不能把合并后的状态当成一个可写对象。

## 确认的问题与处理

| 问题 | 具体触发 | 修复 |
|---|---|---|
| 中央替换撤销既有分配 | 已分配到 A 的 Skill，在顶层重新安装或从 B 导入同名内容 | intake 仅处理明确目标，合并已有消费关系，保留禁用状态 |
| 本地修改仍显示同步，采用修改拿到旧指纹 | 中央 `SKILL.md` 修改后扫描 | 使用经过验证的实际指纹、描述、内容类型；准确中央链接继承变化状态 |
| 历史风险误代表新内容 | 接纳中央本地修改 | 显式采用时重新审计，并核对审计后内容指纹；审阅后再次变化则拒绝提交 |
| 高风险安装 / 导入自动确认 | Desktop 两个快捷入口拿到高风险计划 | 保留原计划，进入已有风险审阅界面，确认前不提交 |
| 同名副本操作错位 | 中央和外部副本被合成一张卡片 | Inspector 使用真实 item，并提供实际位置选择；切换副本清空替换选项 |
| 开发预览中来源解析被误取消 | StrictMode 先 cleanup 再 setup | 重置关闭标志，保留请求代次校验和取消清理 |
| 正文详情陈旧 | 同路径内容变化，或外部副本没有 managed hash/timestamp | 托管副本按内容版本失效；无指纹副本按 inventory 刷新失效；迟到响应不覆盖新选择 |
| 仓库有无关提交时永久提示更新 | GitHub SHA 变化，但该 Skill 下载内容完全相同 | 可确认仅更新来源版本记录；不替换目录或链接；事务内再次检查内容 |
| 更新检查缓存与重试时间错误 | 新响应无 ETag；时钟回拨；Retry-After 为秒数或 HTTP 日期 | 新响应清旧 ETag，安全纠正未被并发修改的未来时间，重试时间规范为 RFC3339 |
| 删除遗留相对断链 | 中央副本缺失，Agent 链接使用相对路径 | 使用已有词法归属判断，只删除确属该中央 Skill 的链接，保留其他断链 |
| 展示实际无法执行的收敛动作 | 中央修改、禁用漂移和独立外部目录共用泛化按钮 | 按已有 Core 契约提供动作；独立目录不作为可覆盖的 managed link |
| 多目录同名开关命中另一份副本 | 同一 Agent 在共享目录和自己的目录都消费同名 Skill | 界面传入所选 target ID；CLI 支持 `--target`，有多个目标却未指定时拒绝操作 |

### 生命周期不改变无关消费者

见 [`build_install_plan`](../core/src/resources/skill/ops.rs:700) 与同文件 `install_settings_after`。顶层中央 intake 的空 Agent 选择表示只处理资产；不能解释成“撤销所有已有分配”。同名导入仅把实际导入目录和明确新目标放入写集合，其他消费者继续通过中央链接读取新资产，已有 `enabled=false` 保持。

明确调整消费关系仍使用 assignment / asset consumption API，不把中央 intake 的保留规则复制到所有操作。

### 实际观测和风险基线

见 [`scan_central`](../core/src/resources/skill/inventory.rs:622)、[`plan_adopt_observed_skill`](../core/src/assets/planner.rs:1160)。损坏或无法验证的内容不再借用旧的可用指纹；独立外部副本也不继承中央来源和历史风险。正常扫描不反复审计每个文件树，采用修改时才审计新内容并核对指纹。

列表和提交的检查各有作用：列表解释当前状态；提交仍重新检查原计划、内容和目标。显示缓存不能成为写入授权。

### 更新仅改变来源版本

见 [`build_update_plan`](../core/src/resources/skill/ops.rs:1092) 与 [`validate_metadata_only_content`](../core/src/resources/skill/transaction.rs:1522)。远端 SHA 变化只能提示需要检查；下载并验证内容相同后，才允许只推进来源记录。检查阶段没有新增下载整个仓库或子目录扫描。

### UI 的身份和异步边界

见 [`SkillInstallDialog`](../desktop/src/components/SkillInstallDialog.tsx:321)、[`SkillsView`](../desktop/src/components/SkillsView.tsx:130)、[`SkillInspector`](../desktop/src/components/SkillInspector.tsx:229)。普通低风险导入保留原有直接执行体验；高风险路径展示原计划。关闭后取消计划，后续旧解析和提交回调受关闭标志与代次检查约束。

一张卡片继续展示一个名字，来源分类和三行描述保留；详情位置选择解决具体副本的操作问题，不新增第二套资产编排。

## 验证与范围

已补必要的回归测试源码，覆盖消费关系保留、禁用状态、同内容版本更新的 inode / CAS、相对断链、采用修改的重新审计和二次编辑拒绝，以及原计划风险确认、真实副本定位和外部详情刷新。

按照项目极速模式，没有执行 cargo/npm 测试套件、fmt、clippy 或故障注入；生产和测试源码编译、前端构建、隔离 CLI 定向检查分别记录结果。真实 HOME 只用于最后的本地开发预览，未用于操作复现。

用户明确要求换模型复审后，先进行了独立复核，随后按指定的 6.1 Sol 继续复审并收尾。复审补充的禁用外部目录恢复按钮与无指纹详情失效问题也已修复。没有继续修改 MUX 的模型切换功能。

实际验证结果：Core/CLI 与桌面全目标编译、前端 TypeScript/Vite 构建通过。隔离 CLI 的 8 项检查通过：重装保留禁用关系；采用本地修改后同步且正文与链接不变；同名导入保留其他消费者；按明确物理目标切换并保留另一份关系；禁用状态的外部目录不提供恢复覆盖；相对受管断链清理且独立目录保留；审阅后文件变化拒绝提交；高风险没有显式确认时拒绝安装。

GitHub 同内容更新、缓存时间与界面流程新增了回归源码，本轮未执行对应测试套件或网络故障注入。后续发布前若要验证这些边界，需要单独执行隔离测试和视觉验收，不能用本次编译通过代替。

最终源码的本地 Tauri 开发预览已重启，使用真实 HOME 与 `~/.mux`，窗口标题为「MUX · 本地开发预览」。这一验证阶段没有替换正式安装版；后续交付由独立的正式发布流程处理。

## 确认流程精简

按用户要求避免无意义弹窗：高风险证据、勾选和原计划提交合并在同一个确认窗口，不先发送一次注定会被拒绝的空风险确认，再切到第二个窗口。普通更新、已核验的来源版本记录更新、没有覆盖现有副本的修复，以及低风险导入直接执行，使用轻量通知反馈。删除中央资产、覆盖本地修改和高风险内容保留一次有实际判断内容的确认。

此调整已通过前端 TypeScript/Vite 构建；更新了原计划风险绑定、单次关闭、失败留在同一窗口，以及普通修复/版本记录更新不额外确认的回归源码，未运行测试套件。
