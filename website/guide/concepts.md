# 核心概念

## 中央资产与 Agent 关系

Models、MCPs、Skills 各自有一份中央资产库。**资产**定义内容；**消费关系**定义哪个 Agent 应该使用它。Agent 页面用于选择资产与管理关系，资产的创建、导入、编辑和删除在顶部资源库完成。

| 操作 | 对关系的影响 | 中央资产 |
|---|---|---|
| 添加到 Agent | 建立关系 | 保留 |
| 停用 | 保留关系，暂停生效 | 保留 |
| 解除使用 | 移除指定关系与可安全移除的受管目标 | 保留 |
| 删除中央资产 | 审阅所有消费者并清理受管关系 | 删除或备份移出 |

MCP 与 Skills 每个 Agent 可以使用多个。原生多模型 Agent 可以添加多个 Model，但全局当前模型最多一个；某些桌面客户端在各会话中选择模型。能力限制由实际客户端契约决定。

## MCP 来源与优先级

中央 MCP 目录由已启用来源的并集构成：远程 URL 订阅、本地配置导入、手动添加或粘贴。可选的 Mux 精选属于远程订阅。

同一 `name::transport` 在多个来源出现时，手动来源优先；受支持的旧 discovered 受管来源仍参与目录。其他副本显示为被覆盖，并保留来源信息。传输身份分为 `stdio` 和 `http`，SSE 归入 HTTP；同名 stdio 与 HTTP 是两个独立条目。

Agent 文件中的新发现是外部观测，不属于自动创建的中央来源。显式导入后才能作为中央资产使用。

## 期望状态与实际状态

MUX 记录你希望 Agent 使用的内容，同时读取配置文件和 Skill 链接来核对实际状态。

| 状态 | 说明 |
|---|---|
| 已同步 | 内容与关系一致 |
| 外部新增 | Agent 中存在，MUX 尚未管理 |
| 外部修改 | 已管理内容被其他工具修改 |
| 外部删除 | 关系仍在，实际目标已删除 |
| 无法解析 / 歧义 / 不支持 | 当前目标不能安全读取或无损表达 |

对准确的异常关系，MUX 只提供当前可安全执行的动作：**采用外部、恢复 MUX、解除管理**。新的扫描不会自动采用内容；恢复不会覆盖外部目录、文件或异向链接。

## 同步与恢复

中央变化先持久化，再按 `Agent × 能力 × 实际文件或目录` 分别同步。共享一个实际目标的 Agent 会合并展示影响。某个目标失败时，不回滚其他已完成目标；失败关系保留，并可针对该目标修复或重试。

已有 Agent 配置在备份和并发校验后原地更新，保留路径与 inode，让正在监听的客户端能看到变化。新文件与 MUX 私有文档使用原子发布。提交前内容发生变化时，旧计划会被拒绝。

## 数据布局

```text
~/.mux/
├── settings.json                  # 设置与消费关系
├── assets/
│   ├── mcps/                      # 目录、来源与 MCP 图标
│   ├── models/                    # Provider / Model 元数据
│   └── skills/items/              # 唯一中央 Skill 副本
├── staging/                       # 临时解析与审阅计划
├── journals/                      # 操作与恢复进度
└── backups/                       # 修改前的备份
```

API Key 正文不属于这些公共元数据，中央密钥保存在系统 Keychain。Skill 分配使用指向中央副本的链接。用户目录内的配置路径折叠为 `~/…`；自定义路径与跨机器环境仍需核对。
